## 验证的实际边界

| 环节 | 验证方式 | 能证明什么 |
| --- | --- | --- |
| 快捷键注册与事件路由 | 真实 Carbon 注册，本进程发送事件，回调只计数 | 自己的事件只触发一次；其他签名/ID与缺失ID不触发；注册冲突不破坏原回调；注销、重新注册后旧回调不执行 |
| 截图任务 | 真实 AppModel，注入生成的图片 | 防连按、错误后重试、原图保存、首次发送授权和数据库恢复 |
| 账单内容 OCR | 生成收据进入 captureScreen，再走实际 JPEG、Vision、SQLite | OCR 恢复 `129.00` 和 `TEST-20261018-001`，重开数据库内容一致 |
| 撤回 AI 授权 | OCR 开始时撤权，模型边界配置只会报错的守卫 | 实际 OCR 完成并保存，记录保持等待，模型边界调用次数为 0；不提供伪造模型结果 |
| 人工核对入账 | 明确的领域测试样本，调用真实 confirm | 负金额不入账；手改 `129.10` 保持十进制精度；重开数据库保留来源和修正 |
| 缺失币种预填 | 真实 AppModel 核对草稿与临时 SQLite | nil、空串和空白只在待确认草稿预填 CNY；不覆盖外币或已确认数据；用户改值可保存；确认时仍检查疑似重复 |
| 真实模型抽取 | 显式 `--live-ai`，生成收据走真实 AppModel/OCR/AIClient/SQLite | 本次实测 GPT-5.6 Sol 原始输出金额 `129.00`、币种 `CNY`、订单号 `TEST-20261018-001` 正确；未经修正，先待核对、再确认入账，重开临时数据库仍一致 |
| 真实桌面 | 用户主动触发，随后只读核对原图和数据库 | 单显示器实测已完成截图、真实模型识别、确认入账及同单凭据关联；关闭主窗口后的捕获、权限拒绝和多显示器仍需逐项人工验收 |

普通测试中的图片回调只替代屏幕采集。OCR 与数据库使用实际实现。核对入账用例是领域数据样本，不代表模型抽取准确率。

## 运行离线测试

在项目根目录执行：

```sh
swift run LedgerTests
./scripts/test-capture.sh
./scripts/test-hotkey.sh
swift run LedgerCheck
```

`test-hotkey.sh` 只向自己的进程发送 Carbon 事件，不会生成真实桌面按键或调用截图服务。若系统拒绝注册快捷键，输出 `SKIP`，该环节仍待验收。

## 真实模型测试

API key 是客户端调用公司 RAI/MaaS 的凭据。仓库不包含个人凭据；本机配置不全时，先跑上面的离线测试即可。不要把 key 发到聊天、写入源码或 patch。

本次配置使用 RAI「Red Token Hub → 我的额度」中现有的个人 API Key，仅存于本机登录钥匙串（service：`promise-ledger.maas.api-key`，account：`promise-ledger`）。`~/.config/promise-ledger/model.json` 权限为 `600`，保存 HTTPS 接口、`GPT-5.6 Sol`、应用标识 `seal` 与钥匙串引用，不含明文 key。读取时若 macOS 弹出授权，请在系统窗口完成；不要将系统密码填入聊天。配置及凭据均在仓库外，不随 patch 分发。

本机准备好模型配置及对应钥匙串凭据后执行：

```sh
./scripts/test-capture.sh --live-ai
# 已有配置在其他位置时，只传路径
./scripts/test-capture.sh --live-ai --config /absolute/path/to/model.json
```

该选项只向配置的服务发送程序生成收据的 OCR，不读取真实桌面。检查真实模型先输出金额 `129.00`、币种 `CNY`、订单号 `TEST-20261018-001`，保留待确认状态后才模拟确认，并重开临时数据库核对。不能先人工修正抽取错误再宣称模型通过。失败不自动重试。

配置缺失时程序输出 `LIVE AI BLOCKED`、退出码为 2；这是测试前置条件未满足，不代表模型效果已验证。

## 人工桌面验收

1. 用 `swift run LedgerCheck --make-fixture dist/fixtures/diagnostic-receipt.png` 生成虚构收据，桌面只展示适合测试的材料。
2. 使用 `open "dist/Promise Ledger.app" --args --preview` 打开隔离账本。关闭窗口，检查菜单栏仍有入口且进程存活。
3. 在其他应用中展示虚构收据，主动按 Control + Option + L；检查屏幕权限提示、允许后的截图，以及拒绝后可恢复的错误。系统要求重启时再重试。
4. 检查记录来源为屏幕截图、原图清楚且不含账本自身窗口；有多个显示器时移动鼠标验证目标屏幕。
5. 检查首次 AI 发送同意、撤权后不发送、连续按键不重复执行；用真实模型时核对金额、币种、日期及订单号，再确认入账。
6. 关闭并重新打开主窗口，核对同一预览会话的记录仍在；完全退出后，原快捷键不应再触发该客户端。`--preview` 每次启动都会创建新的临时账本，重启后显示空账本属于预期；原目录不会由应用主动删除，但可能被系统清理。跨连接持久化由上述临时 SQLite 重开测试验证。

这些桌面交互没有被自动截图替代；在执行前不要标为通过。单张虚构收据通过也不能推导真实账单的总体准确率。

## 本机构建更新后的屏幕授权

当前脚本使用 ad-hoc 签名，改代码后重建可能使旧的录屏授权不再匹配新版签名。若系统设置显示已开启，但客户端仍报未授权，先退出账本，再移除旧项并添加当前构建。若旧签名要求仍残留，可使用 macOS 官方工具只重置此应用的录屏授权：

```sh
tccutil reset ScreenCapture life.promiseledger.mac
```

随后由用户重新授权同一份构建，按系统提示重开应用；期间不要再次构建或重签名。此命令不影响其他应用。当前本机曾通过目标 TCC 日志确认旧签名不匹配，单应用重置后恢复；不把“设置开关开启”单独当作授权生效的证据。机制说明见 [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。
