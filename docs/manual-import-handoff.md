## 交付范围与协作边界

手工上传链路为：文件选择或 Finder 拖拽 → 只读预览 → 用户确认 → 本地保存与图片去重 → 用户授权后 OCR / AI → 人工核对入账。

| 模块 | 已交付行为 | 负责边界与主要文件 |
| --- | --- | --- |
| 选择与拖拽 | 最多 10 张；忙碌时提示；拖拽地址异步解析；取消后的旧回调不覆盖新选择 | 手工上传：`Sources/PromiseLedger/AppModel.swift`、`Sources/LedgerMac/ImportSelection.swift` |
| 导入前预览 | 缩略图、文件名、大小、有效性；移除、取消、仅确认有效图片；预览不保存凭据、不建单 | 手工上传：`Sources/PromiseLedger/ImportPreviewView.swift`、`ImportSelection.swift` |
| 逐文件反馈 | 已导入、重复、失败独立显示；失败不阻断后续有效文件；重新选择入口 | 手工上传：`Sources/LedgerMac/ImportBatch.swift`、`Sources/PromiseLedger/ImportResultsView.swift` |
| 图片读取 | PNG/JPEG/HEIC/TIFF；单张 ≤ 41,943,040 字节；像素总数 ≤ 100,000,000；归一化保存与哈希；确认时校验预览内容 | 手工上传：`Sources/LedgerMac/ImagePipeline.swift` |
| OCR、识别、复核入口 | 复用现有串行任务、AI 授权、失败提示、手动继续与人工入账 | 与 Agent / 数据库同学共同联调；本轮不调整模型、提示词、数据库或状态持久化规则 |
| 系统快捷键截图 | 与手工上传共用后续识别链路 | 快捷键同学负责捕获、权限和系统快捷键验收 |

“已导入”表示本地凭据接收成功。“待确认”表示识别完成，仍需人工入账。图片重复与订单重复是两层判断；不同截图是否属于同一订单由现有订单去重逻辑处理。

“原图保留”在本项目中指独立保存的规范化 JPEG 凭据副本，可能缩放，非输入文件逐字节归档。输入文件不会被应用修改。预览内容校验使用输入文件字节哈希；仅修改文件系统时间不触发拒绝，改变文件字节后须重新选择确认。

## 隔离界面验收：准备与基本操作

先退出已经运行的账本实例（关闭窗口不等于退出）。生成专用虚构图片：

```sh
mkdir -p dist/manual-import-qa
swift run LedgerCheck --make-fixture dist/manual-import-qa/original.png
swift run LedgerCheck --make-alternate-fixture dist/manual-import-qa/alternate.png
cp dist/manual-import-qa/original.png dist/manual-import-qa/duplicate.png
cp dist/manual-import-qa/original.png dist/manual-import-qa/changed.png
cp dist/manual-import-qa/original.png dist/manual-import-qa/deleted.png
printf 'invalid image fixture\n' > dist/manual-import-qa/broken.png
open 'dist/Promise Ledger.app' --args --preview
```

确认处于「AI 账本 · 隔离预览」。`--preview` 使用新的临时目录、隔离 AI 授权；普通导入验收选择「暂不识别」，避免模型调用。下述各组要求“新账本”时，退出实例后再次带 `--preview` 启动。

| 步骤 | 操作 | 验收标准 |
| --- | --- | --- |
| 只读预览 | 选择 original、alternate、broken；等待检查完成 | 前两张有缩略图和大小，broken 有错误；此时账本记录不增加，无识别请求 |
| 移除 / 取消 | 移除 alternate，再取消整批；重新选择 | 取消后记录不增加；新选择不会恢复已取消的行 |
| 确认与去重 | 新账本选择 original、duplicate、broken，确认可导入的图片，暂不识别 | broken 在预览中被排除；批处理针对有效的 2 张，结果为 1 导入、1 重复；不能把预览错误算成导入后的失败行 |
| Finder 拖拽 | 将同组文件从 Finder 拖入窗口，重复上述操作 | 进入同一预览与确认流程，结果符合相同前置数据下的去重规则；需真实跨窗口操作，自动测试不替代此项 |
| 无效输入 | 仅选择 broken；或拖入非图片、空文件 | 有明确错误；没有有效文件时不能确认；不产生账单 |

### 复现预览后替换和删除

使用新账本，选择 `changed.png`、`deleted.png`、`original.png`，等三张预览均有效，保持预览窗口打开。在仓库根目录另开终端，仅操作刚生成的测试文件：

```sh
cp dist/manual-import-qa/alternate.png dist/manual-import-qa/changed.png
rm dist/manual-import-qa/deleted.png
```

回到应用确认导入，选择暂不识别。预期共 3 张：1 导入、0 重复、2 失败。

- changed：`图片内容已变化，请重新选择并确认后导入。`
- deleted：`图片文件已不存在，可能已被删除或移动，请重新选择并确认后导入。`
- original 正常保存；失败项不应新增记录或残留凭据。点击「重新选择图片」，选当前 changed 并再次确认，应成功保存第二张凭据。

同大小、同修改时间替换和仅文件系统时间变化的细节由 `ChangedFileTests` 复现。再次执行本节前，重新运行准备命令恢复测试文件。

### 数量、格式与超大图

10/11 个输入可用虚构收据的 11 份副本检查：选 10 个应进入预览并逐文件处理；相同内容只会形成 1 条记录，其余为重复。选择 11 个应整批拒绝且不新增记录。**验证 10 条独立记录需要 10 张内容不同的有效图片**，复制文件不能证明这一点。

精确 40 MiB / 多 1 字节用 `ImportTests` 检查。HEIC 和超 1 亿像素需要另行准备真实编码、可解码的专用样例，改扩展名不能代替格式测试。团队补测实际 iPhone HEIC、方向信息、长截图及高分辨率样例时，分别记录预览、保存与 OCR 结果。

## 可选真实模型与故障验收

真实模型步骤会发送合成收据 OCR 并产生模型用量。复用测试人员本机已授权的 `~/.config/promise-ledger/model.json` 和 Keychain，模型统一 GPT-5.6 Sol；配置结构参考 `config/model.example.json`。其他同学的机器不自动具备当前开发机配置，先由配置负责人完成授权；不把 key 写入命令、截图、仓库或验收日志。

1. 新隔离预览中导入 original，确认后同意识别。应依次完成 OCR、AI，进入待确认，核对虚构金额 CNY 129.00。
2. 对照凭据人工确认入账，检查只入账一次；再次导入相同图应提示重复。
3. 仅需程序级诊断时可执行 `swift run LedgerCheck --live-ai`，它只发送生成的收据文字，但不能替代界面人工确认验收。

故障复测要求团队准备隔离的故障注入环境，并记录请求次数。以下是验收协议，**当前仓库没有一键断网 / 超时 / 429 注入命令**；此前临时工具不能作为其他机器已具备的前提。不得通过更改共享模型服务或真实账本制造故障，也不要用假成功响应声称真实模型通过。

| 场景 | 注入与操作 | 必须记录的结果 |
| --- | --- | --- |
| 连接中断 | 在测试环境令单次识别连接断开，等待失败 | 可理解的失败提示、可查看凭据、手动「重新识别」入口 |
| 超时 | 让请求持续无完整响应，覆盖实际 90 秒请求上限 | 超时后进入失败；停止忙碌状态；记录耗时和请求数 |
| 限流 | 隔离端返回 429，可带 Retry-After | 失败提示；等待超过 Retry-After 后仍不自动发送 |
| 手动恢复 | 恢复连接 / 服务后，主动点击一次重新识别 | 同一记录进入待确认；再人工入账，最终只计入一次 |

每个场景比较前后记录 ID、凭据哈希 / 文件、记录数与请求数。建议失败后观察至少 120 秒，并记录实际观察时长；观察期间请求数不增加。有限观察不等于无限时间保证，需要结合代码无自动重试路径的检查。此前证据含连接中断，不应扩展为所有离线、DNS 或 TLS 故障均已通过。

## 重启与强制退出：固定隔离账本

`--preview` 每次创建新目录，重开后空账本是预期行为，不能作为恢复结论。当前应用没有公开的“指定预览目录”启动参数。

团队可在**专用 macOS 测试账号或专用测试机**内正常启动应用（不带 `--preview`），将该账号的 Application Support 作为固定隔离账本；只导入合成数据。不要在日常账号的真实账本上执行此流程。也可先把此前固定目录测试工具固化入库，再使用该工具复测；这属于后续工作。

测试账号若做 AI 联调，需配置负责人在该账号独立配置模型凭据。分别执行三轮，每轮记录凭据、记录 ID、状态和请求数：

1. 识别进行中使用 Command + Q 退出；重开同一账本。未完成任务恢复为等待状态，无自动模型请求；点击「开始识别」后能继续。
2. 识别失败后正常退出；重开，失败记录及凭据仍在，主动「重新识别」可继续。
3. 识别进行中，通过活动监视器核对测试应用进程后强制退出；重开同一账本，检查与第 1 项相同的恢复行为。

每轮恢复后观察至少 120 秒不操作，确认请求数不增加；随后手动继续并人工确认。检查记录 ID 延续、凭据可打开、记录不重复、最终只入账一次。关闭窗口测试只能验证菜单栏常驻，不能代替退出或强制终止。
