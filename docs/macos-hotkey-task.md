# macOS 快捷键截图识别：开发 Prompt

你正在维护 gitover22/promise-ledger。我负责「客户端快捷键自动识别」，请基于现有 MVP 完成开发、排错和验收。改动在独立功能分支提交，通过 PR 交由团队审核，不直接修改主分支。

## 先检查现状

先读取 AGENTS.md、README.md、当前提交和相关实现，确认客户端技术栈、驻留生命周期、全局快捷键、截图权限、AI 接口、任务状态及数据库写入方式。现有版本是原生 macOS SwiftUI/AppKit 应用，已有菜单栏、ScreenCaptureKit、Vision OCR 和 SQLite；以实际最新代码为准，不重新搭建应用或数据库。

## 我的任务

客户端启动并驻留后台后，用户在其他应用中也能主动按快捷键截屏。截图交给已有识别链路，提取账单信息并保存到现有数据库。关闭主窗口后功能仍可用；只有显式退出才结束驻留。

当前 MVP 使用 Control + Option + L 截取鼠标所在显示器的全屏，排除账本自身窗口。先沿用已有行为，保证清晰度和多显示器选择正确；不擅自增加持续录屏、定时截图或其他输入模式。

必须处理首次屏幕授权、拒绝和撤销权限、快捷键冲突、连续触发、截图失败、AI 失败、数据库不可用等情况。错误要可见、可恢复；失败后能由用户重试，不能静默失效或无限自动重试。

## 与手工上传的边界

手工上传入口由另一位同事负责。两条入口必须复用已有的图片标准化、OCR、AI 解析、状态流转和数据库写入链路。截图和上传同一张规范化图片时复用既有记录，不能重复入库、覆盖已确认结果或误改原始来源。

我负责截图入口的闭环及必要的共用接口修复。不要重写同事的上传界面，也不要扩展 PDF、邮件、网页监控等未约定功能。

## 数据与 AI 约束

沿用现有模型配置和团队约定的 GPT-5.6 Sol，不另选供应商。密钥只通过本机现有凭据机制获取，不打印、不写进源码、日志、数据库或 patch。

保留首次 AI 文字发送同意与撤回机制。当前实现是本地 OCR 后向配置的 MaaS 发送文字，原图留在本机。提取结果自动保存为「待确认」，用户核对后再正式入账；不要把自动存储改成自动确认。

保留原图、OCR、来源和失败状态，金额沿用 Decimal。数据库初始化失败后要能显式重试；数据库持续写入失败时必须停止当前识别队列，等待用户处理，不能热循环。

## 验证与交付

先复现问题，再做必要的最小修改。运行现有核心测试、合成收据 OCR/存储诊断及应用构建。新增测试覆盖初始化失败恢复、重复按键防重入、截图失败后重试、首次同意门控、截图与上传并发去重、数据库写失败停止队列。

测试仅使用合成图片和隔离临时数据库，不自动截取真实桌面，不写入真实账本。真实系统授权、后台全局快捷键、跨显示器截图和完整 AI 入库另列手工验收清单；未经实际验证的项目不能声称通过。

最后提供修改文件、修复原因、执行过的测试及结果、剩余人工验收项和 PR。若上游已经修复相同问题，复测后跳过重复改动。
