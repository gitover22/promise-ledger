# 你的智能 AI 账本 · Promise Ledger

轻量原生 macOS 客户端：截下订单，或导入手机截图，让 AI 整理账单，并保留交易承诺的原文依据。

当前为可运行的 0.3.1 开发版，使用 SwiftUI / AppKit、ScreenCaptureKit、Vision 和 SQLite，无第三方运行时和包依赖。最低 macOS 14；当前开发构建为 Apple Silicon 原生程序。

## 启动

需要 macOS 和 Xcode Command Line Tools，不要求安装完整 Xcode：

```sh
./scripts/run.sh
```

脚本会编译 release 程序、生成图标、打包并进行本机 ad-hoc 签名，再打开 `dist/Promise Ledger.app`。只构建不启动可运行 `./scripts/build.sh`。首次构建需要等待 Swift 编译系统框架。

这是本机开发构建，尚未做 Developer ID 签名、公证、自动更新或 App Store 分发；不可视为已完成可分发的安装包。升级构建后，系统有时需要重新确认屏幕录制权限。

## 第一条账单

1. 打开应用，点「导入图片」，或从 Finder 把 PNG / JPEG / HEIC / TIFF 图片拖入窗口。单次最多 10 张；单张限制为 40 MiB（界面显示 40 MB）。
2. 在导入前预览中核对缩略图、文件名、大小及错误提示，可移除图片或取消整批。点击「确认导入 N 张」才保存有效图片；预览阶段不建单、不调用模型。
3. 查看逐文件「已导入 / 重复 / 失败」结果。预览后文件内容变化或被删除时，该文件会被拦截并提示重新选择确认，同批其他有效图片继续处理。「已导入」只表示本地保存成功，不代表 AI 识别或入账完成。
4. 首次识别前阅读 AI 文字发送说明，选择「同意并识别」或「暂不识别」。原图不上传；识别出的全部 OCR 文字会发送至配置的 MaaS 服务，可能含姓名或地址，请先检查订单内容。暂不识别时保留本地图片，之后可主动「开始识别」。
5. 等待「正在读取图片文字 → 正在识别账单」完成，记录进入「待确认」。打开记录，对照原图核对金额、币种、日期或分类，点击「确认入账」。「识别信息」中保留模型自评和提示词版本，模型自评不是经过校准的准确率。
6. 截图时在目标订单页面按 **Control + Option + L**。多显示器环境会截取鼠标所在显示器的完整画面，并排除本应用窗口。屏幕其他可见内容也可能被 OCR，请注意隐私。

手工上传的交付范围、协作边界、可复现步骤、已通过及待补测项目见 [手工上传交付与验收说明](docs/manual-import-handoff.md)。

第一次截图需要在系统设置的「隐私与安全性 → 屏幕与系统音频录制」授权。拒绝后不会绕过系统限制；仍可使用图片导入。系统要求时重启应用后重试。

模型未识别出币种时，「待确认」详情会按人民币 `CNY` 预填，并显示默认值说明；可直接核对确认，也可改成其他币种。已识别出的 USD、JPY 等币种保持不变。默认值只用于编辑草稿，确认前不改写原始识别结果；金额和日期缺失时仍需核对填写，不会自动入账。

关闭主窗口不会退出程序；菜单栏保留账本图标，可截图、导入或重新打开窗口。退出请使用菜单栏的「退出 AI 账本」或 Command + Q。应用没有持续录屏、后台轮询或自动调用模型；仅处理用户主动触发的任务。开机自启暂未实现。

## AI 配置与密钥

配置读取自当前 macOS 用户的 `~/.config/promise-ledger/model.json`。配置和钥匙串凭据不随仓库分发；可先运行离线测试，真实 AI 测试需要本机有效配置。不要把密钥贴到聊天或写进源码。

- 默认模型：`GPT-5.6 Sol`；不因某次 GLM 测试而切换默认模型。
- 服务：已配置的 Rednote MaaS Chat Completions HTTPS 端点。
- 从配置读取 Authorization 请求头、Bearer 前缀、流式开关及 `include_usage`，不在代码中另选供应商。
- 应用标识：用户指定的 `seal`，通过 `x-maas-app-id` 请求头传递；账单抽取场景使用 `x-maas-scenario: bill-extraction`。
- 密钥只在调用进程内，通过 `/usr/bin/security` 读取 macOS 钥匙串，捕获而不显示 stdout；service 为 `promise-ledger.maas.api-key`，account 为 `promise-ledger`。
- 密钥不进入前端状态、源码、SQLite、错误信息或日志。仓库中的 `config/model.example.json` 仅为不含密钥的配置结构参考，不会覆盖本机配置。
- 不将密钥复制到 H20、其他服务器或 Pod。未来如需远程服务，必须另外授权运行时 secret 注入。

本版以 **本机 Vision OCR + 文本模型** 实现图片理解，不假定 MaaS 支持图片输入，也不将完整原图上传给模型。流式响应必须收到 `finish_reason=stop` 和 `[DONE]` 才接受结果；中断或截断不会被当成成功账单。

当前 Mac 的原生 URLSession 与该 MaaS 端点实测发生 TLS 握手失败，而系统 curl 可正常完成严格校验的请求。因此本版使用 `/usr/bin/curl` 作为单次请求传输层：密钥和请求体只通过进程 stdin 传入，不出现在命令行参数或临时文件中。保留 HTTPS 及证书校验，不读取用户 `.curlrc`，不跟随重定向，不自动重试请求。

## 代码结构

- `LedgerCore`：账单与承诺模型、字段校验、MaaS 配置与客户端、SSE 完整性校验、SQLite 持久化。
- `LedgerMac`：图片归一化与 SHA-256 去重、本地 OCR、按需全屏截图、Carbon 全局快捷键。
- `PromiseLedger`：应用生命周期、菜单栏、串行识别任务队列、SwiftUI 首页、复核和隐私设置。
- `LedgerCheck`：只使用自动生成的虚构收据进行 OCR / AI / 数据库存储诊断，不读取真实屏幕，不写入用户账本。
- `Tests/LedgerCoreTests`：金额精度、日期、原文证据、非账单拒绝、完整与中断流、SQL 参数化、去重、重启恢复测试。

## 数据与恢复

本地数据位于 `~/Library/Application Support/PromiseLedger/`：`ledger.sqlite3` 及 WAL 辅助文件保存记录；`Images/` 保存规范化的 JPEG 原始凭据副本。OCR 文字、订单号、模型抽取结果也会留存在数据库中。导入手机图片时应用会生成独立副本，不会修改用户原文件。

目录权限为 700，新建数据库与图片权限为 600。当前尚无应用层加密；请使用 FileVault 保护磁盘。程序没有账户体系和云同步。备份时退出应用后复制整个数据目录，不能只复制正在写入的 SQLite 主文件而忽略 WAL。

任务串行处理，以免同时触发大量 AI 请求。相同规范化图片会复用原记录，不重复调用模型；不同图片仍需提取新证据，再进行订单级去重。模型失败或网络中断会保留凭据并显示重试入口；应用重启会把未完成任务恢复为等待状态，不会自动重新发送。对仍在等待的记录点击「开始识别」继续。

## 订单级去重（0.2）

- 有明确原文依据的完整订单号，加同平台或同商家范围一致时，自动关联已有订单。大小写、全半角和空白保守归一化，但不猜 O/0、不补掩码、不删除有意义的分隔符。不同平台的相同编号不能直接视为同单。
- 缺少订单号、仅同商家/同日期/同币种/同金额，或者同编号却无法确定归属时，只标记「疑似重复」。用户须比较候选后选择关联原订单或确认是不同订单，未解决前不能入账。明确不同的订单号不因同价同日而合并。
- 新截图保存为关联凭据，保留自己的图片、OCR、承诺和提示词版本；首页不再显示第二笔账单，不重复计入金额，也不覆盖已确认字段。在原订单详情的「关联凭据」中查看追加来源及原文。
- 入账时重新检查，不能靠旧界面快照绕过。唯一订单 key 索引、IMMEDIATE 事务和数据库判断共同约束并发。用户明确保留不同订单后，修改字段或新增候选会触发重新核对。
- 升级首次打开 v1/v2 数据库，会先在 `Backups/` 生成原版本的独立 SQLite 备份，再迁移到 v3。v1 先迁移订单去重，再增加待办表；v2 只增加待办表，不改写已有账单。图片与旧记录均保留，失败不会静默清空数据，不支持旧版程序降级打开。

排重受 OCR 和输入完整性限制。缺失、遮挡或误读订单号，且没有可比较的商家/金额/日期时，不能保证自动识别同单，仍需用户核对；不以模糊相似度静默合并。

## 产品化 system prompt（0.2）

`Sources/LedgerCore/LedgerSystemPrompt.swift` 根据[产品 REDoc](https://docs.xiaohongshu.com/doc/c88851b328440ed0d68ccd1e035a6193)设计，版本为 `2026-10-18.promise-ledger.v2`，每次结果保存 `prompt_version`。文档中早期浏览器/Web 形态不改变当前原生 macOS 范围。

提示词明确产品不是只做支出分类，而是保存可验证的交易身份与承诺：先区分订单号、平台、商家和支付/物流编号，再提取金额事实及承诺方、条件、用户动作、原文引用。客服承诺或规则材料允许无金额并作为同单证据；不因缺少金额丢弃承诺。

OCR 以 JSON 字符串数据传入，不与系统消息拼接，不传其他历史账单或密钥。代码再次校验订单号引用、承诺引用与绝对日期，相对期限原样保留而不擅算日期。模型只提取事实，不允许声称已发送提醒、完成持续监控、作出法律判断或自动退款；待办是用户另外确认的客户端功能。此版仍是提示词约束加本地解析，未声称强制 JSON Schema 或绝对防提示注入。

数据库初始化失败时，界面会提供「重试初始化」，恢复存储条件后可直接重试。识别过程中如果连失败状态也无法写入数据库，队列会停止并提示手动重试，避免反复写库。截图与图片导入并发提交相同规范化图片时，会复用同一条记录并保留已有的确认状态和识别内容。

金额使用十进制字符串与 `Decimal`，不使用二进制浮点进行入账计算。首页仅汇总有明确交易日期且已确认的当月金额，不折算币种，也不将导入日期充当交易日期；多币种时显示「多币种」，不混加金额。这是账单确认金额，不是对退款或待付款作会计处理后的净支出。

承诺只保留能在 OCR 中匹配到原文引述的内容；不凭商品类别推断七天无理由、保价或保修权益。日期缺失时不猜测年份或计算到期日。本版不提供系统推送、邮件提醒、网页监控、退款操作或法律判断。

## 客户端待办提示（0.3）

账单识别的「待确认」与交易跟进的「待办事项」相互独立。原订单入账后，在详情的承诺下点击「添加待办」，或点击「新建待办」。同一订单的关联凭据也可以作为待办依据；未确认的 AI 承诺不会自动排期。无金额的补充材料需要先关联已确认的原订单。

- 「今天」显示今天需要处理的事项；「本周」按周一至周日，「本月」按自然月，从今天起查看尚未逾期的待办。周/月包含今天，数字不相加；跨月的一周可能包含下月事项。
- 逾期事项始终单列，跨日不会消失。未指定日期的事项进入「未定日期」；「全部待办」还包含本月以后的事项。
- 处理日期由用户确认，可编辑，也可留空。AI 提取到有依据的绝对日期时仅预填；「三个工作日」等相对期限不自动换算，用户的跟进日期不等于商家承诺的法律截止日。
- 事项可以标记完成、取消（保留历史）或恢复；完成待办不更改订单付款状态。相同订单、规范化事项和日期的重复添加复用原待办，包括已完成历史，防止重复点击把已完成事项重新提醒。不同措辞的手动事项仍需用户判断，暂不做语义合并。
- 打开或从隐藏状态重新打开客户端时，首页显示一张可收起的摘要卡。可在「设置与隐私」关闭此提示；待办列表仍可使用。常驻应用跨日、唤醒或切回前台会刷新日期，不需要调用 AI。
- 当前仅应用内展示，不申请系统通知权限，不在每天 9:00 弹窗，也不发送邮件。未来计划：每天 9:00 邮件摘要、邮箱配置与发送可靠性；关机后仍需准点发送时另行设计服务端调度。

数据库 v3 新增 `reminders` 表，保存稳定待办 ID、来源凭据外键、事项、可空的日期、原文引用、pending/completed/cancelled 状态与创建/更新时间。来源外键不随订单合并丢失，读取和去重时解析到当前原订单。新增、编辑、状态修改均在 IMMEDIATE 事务中完成；旧账单不会被自动生成待办。

## 验证

```sh
# 不访问网络、不读取密钥；使用独立测试程序，无需 XCTest 或完整 Xcode
swift run ImportTests
swift run LedgerTests
swift run LedgerCheck

# 截图任务、实际 Vision OCR 与恢复测试：合成图片、临时账本，不调用 AI
./scripts/test-capture.sh

# Carbon 快捷键注册、事件识别和注销：只计数，不触发真实截屏
./scripts/test-hotkey.sh

# 可选：走真实 AppModel 的截图任务 -> OCR -> AI -> 复核入库
# 只发送生成收据的文字；可用 --config 指定现有模型配置文件路径
./scripts/test-capture.sh --live-ai

# 可选真实模型测试：只发送程序生成的虚构收据 OCR
swift run LedgerCheck --live-ai

# 可选产品回归：4 次真实模型调用，只发送虚构资料
swift run LedgerCheck --live-regression

# 生成一张可在界面中手动导入的虚构收据
swift run LedgerCheck --make-fixture dist/fixtures/diagnostic-receipt.png
swift run LedgerCheck --make-alternate-fixture dist/fixtures/alternate-receipt.png

# 可选：使用全新的隔离临时账本验收界面（先退出已运行的实例）
open "dist/Promise Ledger.app" --args --preview

# 纯本地待办界面演示：隔离临时账本 + 明确标注的合成订单，不调用 AI
open "dist/Promise Ledger.app" --args --preview-reminders
```

`--preview` 模式会在临时目录创建新的空账本并隔离 AI 发送授权，不生成假模型结果，也不写入真实账本。手动导入虚构收据后可以验证完整的授权、识别、复核与入账流程。每次启动都会创建不同的临时账本，因此不能用它复测同一账本的重启恢复；恢复验收见交付说明。退出后正常启动即可回到真实账本。

`--preview-reminders` 会额外生成标注为「非 AI 识别」的合成订单及今天、逾期、未来、日期待定、已完成事项，供离线验收。它们只存在于独立临时目录，不是真实模型调用结果。

屏幕授权与系统级快捷键需要在真实桌面手动验收；无权限时不能仅以编译通过声称截图已验证。OCR 质量取决于截图清晰度，文字识别不保证恢复原始视觉布局；多笔订单或金额歧义会交由用户复核。

快捷键入口的开发范围和验收约束见 [开发 Prompt](docs/macos-hotkey-task.md)。手工验收时应分别检查：关闭主窗口后的快捷键触发、首次授权与拒绝后重试、权限撤销、快捷键冲突、多显示器目标选择，以及真实模型识别后的待确认记录。测试前使用隔离预览账本，并仅截取适合发送给模型的测试材料。

`test-hotkey.sh` 会短暂注册快捷键，并只向测试进程投递 Carbon 事件；它不会合成桌面键盘输入。如果无法注册，会明确输出 `SKIP`，不能算作快捷键验证通过。本地测试覆盖与待验收项见 [快捷键功能验收](docs/hotkey-acceptance.md)。

平台接口参考：[Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager)、[Apple Vision OCR](https://developer.apple.com/documentation/vision/vnrecognizetextrequest)。
